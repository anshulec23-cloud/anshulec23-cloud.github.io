01Problem

A conventional industrial IDS sniffs network traffic and raises an alert. By the time anyone reads it, the command has already reached the actuator. Physical processes do not wait for a SOC queue.

Four failure modes drove the design:

  • Coordinated multi-variable stress. A setpoint that is harmless against its own threshold alarm can destroy equipment when combined with another variable's current state — raising temperature while pressure is already elevated. Single-variable alarms are structurally blind to this. It is the diagonal boundary in the console above.
  • Field device hijacking and replay. Industrial fieldbuses are usually unauthenticated. Anyone with bus access can inject forged telemetry or setpoints.
  • Telemetry staleness. When sensors drop out, traditional interlocks tend to fail open — they skip the cross-variable check rather than refusing the command.
  • Uncontained cascades. A compromised node stays on the control network while someone decides what to do about it.
02Design

Zero trust, meant literally

Every sensor frame is checked three ways before it influences anything: schema structure, timestamp freshness under 120 seconds, and a FIPS 198-1 HMAC-SHA256 signature over a canonical serialisation. A frame failing any check is dropped, and a setpoint arriving without fresh telemetry behind it is refused rather than waved through. Press stale telemetry in the console to watch that path.

Keys nobody has to provision

New ESP32 slaves announce themselves on the bus and an operator approves each with one click. Session keys are derived per device with X25519 and HKDF-SHA256 — no shared secret, no pre-provisioned key material, one firmware image for every node because IDs derive from the MAC. Boot and sequence numbers make replay detectable, which is what the inject replay frame button exercises.

The part worth arguing about

The machine-learning classifier does not decide whether to quarantine a device. Deterministic rules and the trust score do that. The Random Forest only names the attack — fdi_spike, stuxnet, thermal_drift, sensor_fault, normal — and passes that label, with its confidence and the matching MITRE ATT&CK for ICS technique, to the reporting and financial layers.

That split is deliberate. A model that goes quiet, drifts, or is adversarially nudged cannot weaken the defensive response, because the response was never conditional on it. The ML makes an incident legible; the rules make it safe.

Re-arming is manual

Pulling the setpoint back inside the envelope does not close the relay. An operator re-arms it, and the gateway refuses to re-arm while the commanded state is still unsafe. Automatic recovery would let an attacker oscillate across the boundary and ride the gap.

04Beyond detection

Each approved device carries a financial profile. While an incident is live the loss engine computes actual loss, projected loss if left unfixed, the catastrophe avoided, time-to-fix and restabilisation cost, expressed through FAIR and regulatory exposure. A one-click report maps it onto NIST SP 800 controls with ML-selected mitigations and recovery times.

Operator actions — logins, setpoint changes, rule edits — are logged against the verified 3D spatial coordinates of the terminal they came from, so an insider action carries a location and not just a username.

A localhost-only, token-authenticated red-team backend drives a staged eight-attack campaign against the running system, so the defence and the loss figures can be exercised rather than asserted.

05Limits
Read this before trusting the numbers

The enforcement path has been exercised on an ESP32 bench with simulated process dynamics, not on a production plant. The portable USB attack-drill runner is distributed separately and is not in the repository. Where the README and docs/ disagree, docs/ reflects the actual code.

The stability manifolds encode a model of the process. A model that is wrong about the physics will be confidently wrong about safety — which is exactly why the deterministic invariants sit alongside the learned policy rather than behind it, and why the relay is a physical interrupt rather than a software flag.

The console above is a faithful toy: same envelope test, same fail-closed staleness behaviour, same manual re-arm. It is not the gateway, and it proves nothing about the gateway's behaviour under real bus timing.
